## Dependencies and the lead order (J8NIX 6.0, 14 Nov 2026) — keeps "Do this first" right without Dave

The app puts ONE item on top: the open thing only Dave can do that unlocks the most. Order: actionable first → **unlocks** (how many open items it blocks, counted through chains) → money (project at stage ≥ 4, or in Revenue/Finance) → deadline (🔴 now, a real due date, 🟠 today) → age. Arms keep it true with these calls (same `:org`, same version rule as above):
• Any item can wait on any other: `blocked_by text[]` on public.j8_tasks, public.j8_approvals and public.j8_projects holds ids (t-… task, p-… project, or an approval id). Only write a dependency that is stated: in the item itself (its result, warn, context or Dave's words), or in an open blocker in ops/brain/brain.json loose_ends (put that loose-end id in the task's source). Unsure → leave it out.
• A step only Dave can do = a task, never a vague "you" line: insert into public.j8_tasks (org_id, id, project_id, title, action, why, link, link_text, minutes, owner, sev, source, "by") values (:org, 't-<slug>', 'p-…', '<one short phrase>', '<exact action, where, then what to reply>', '<one line why>', '<direct link or null>', '<link text>', <minutes>, 'dave', 'o', '<source>', '<arm>') on conflict (org_id, id) do nothing; first check no open task already covers it (select id, title from public.j8_tasks where org_id = :org and status = 'open' and owner = 'dave'). Team steps use owner = the unit code (CRO, CMO, CTO…). If the task replaces the project's "you" line, add extra = '{"covers_you":{"p":"p-…","you":"<first 60 characters of that you line>"}}' so the line is not shown twice.
• Set a dependency (append, no duplicates): update public.j8_approvals set blocked_by = case when 't-<slug>' = any(blocked_by) then blocked_by else array_append(blocked_by, 't-<slug>') end where org_id = :org and id = '<id>' and version = <v>; (same shape for j8_tasks / j8_projects). One UPDATE per blocker: an UPDATE … FROM with two blockers for the same row keeps only one.
